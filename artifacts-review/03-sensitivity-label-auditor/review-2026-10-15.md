## Findings and corrections

1. **Daily file ceiling changed in the dedicated article.** Live Microsoft Learn
   now states: "Maximum of 500,000 automatically labeled files in your tenant per
   day" [S1]. The README and downstream planning/evidence instructions previously
   stated 100,000. Updated the documented planning ceiling and both exported
   `autoLabelingDailyCap` values to 500000. **Documentation inconsistency remains:**
   the same article's labeling-progress paragraph still says 100,000, as does the
   separate SharePoint/OneDrive PDF guidance [S2]. The documents and manifest now
   require confirmation before live waves and distinguish a ceiling from observed
   throughput or a Graph assignment quota. No tenant capacity was measured.
2. **Label coverage is not proof of protection or Copilot exposure.** Microsoft
   explicitly supports labels without protection settings [S3]. Copilot treatment
   also depends on permissions, encryption usage rights, DLP, and the experience
   [S4, S5]. Replaced the README/architecture's unconditional protection framing;
   implementation and evidence guidance now distinguish confirmed absence from
   failed/unsupported/unknown collection. Sample exports remain samples.
3. **Beta is not a production-supported dependency.** The organization definition
   route requires application `InformationProtectionPolicy.Read.All`; delegated
   user lookup uses `InformationProtectionPolicy.Read` and the user route. The
   endpoint is still beta and Microsoft's warning says production use is not
   supported [S6, S7]. Replaced tenant-approval-only wording with that boundary.
4. **Licensing requires feature-specific verification.** Manual labeling is not
   equivalent to automatic labeling; generic P2 terminology does not establish
   every service-side entitlement. Clarified feature-specific plans, base service
   plans, and benefiting users from the service description [S8]. Aligned the
   deployment placeholder descriptions without implementing entitlement detection.
5. **Extraction is not a zero-backend-state-change promise.** The v1.0 extraction
   action can refresh item metadata under `Files.Read.All` [S9]. Documented that
   caveat for strict non-mutating validation; did not add a tenant run.
6. **Read-only inspection and collection boundaries clarified.** Added current
   Purview label navigation/read roles [S10, S11] and observation-only migration
   guidance [S12]. Email guidance identifies `MSIP_Labels`, Graph header selection,
   and the lack of a first-class Purview label field [S13, S14].
