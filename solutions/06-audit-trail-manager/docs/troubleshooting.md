# Troubleshooting

| Issue | Likely cause | Remediation |
|-------|--------------|-------------|
| UAL is not capturing Copilot events | Audit is not enabled, the tenant does not have the required audit tier, or recent activity has not propagated yet | Confirm Unified Audit Log is enabled, verify the tenant has Audit (Standard) or Audit (Premium) coverage as required, allow for variable audit record availability because Microsoft doesn't guarantee a specific return time and core services typically appear within 60-90 minutes while other services can take longer, and re-run the audit completeness check |
| Retention policy is not applying | The retention label or policy scope does not include the target Copilot artifact locations | Review Purview policy scope, label publishing targets, workload inclusion, and any exclusions that remove Copilot-related content |
| Microsoft Purview eDiscovery case creation fails | The operator lacks the required permissions or the case role group is incomplete | Confirm eDiscovery Manager access, case permissions, and hold management roles before retrying |
| Evidence export hash mismatch | File encoding or post-export edits changed the JSON after the hash file was created | Re-run `Export-Evidence.ps1`, avoid manual edits after export, and confirm UTF-8 output is preserved |
| Power BI fails to refresh | Graph token expiry, expired gateway credentials, or missing workspace permissions | Re-authenticate the data source, refresh the connection reference, and confirm the dashboard owner still has workspace access |
| UAL ingestion appears disabled only in Security & Compliance PowerShell | `Get-AdminAuditLogConfig` reports that property as false in that session | Check `UnifiedAuditLogIngestionEnabled` in Exchange Online PowerShell instead; see [audit search prerequisites](https://learn.microsoft.com/purview/audit-search) |
| `Check-AuditLogCompleteness` is not recognized | Generated metadata names a workflow placeholder, not a shipped command | Use Purview Audit or Exchange Online PowerShell `Search-UnifiedAuditLog` for authorized manual validation; local monitoring does not query UAL |
| New Copilot retention location is unavailable through older retention cmdlets | The new location uses a different cmdlet family | Use `AppRetentionCompliancePolicy` and `AppRetentionComplianceRule` cmdlets for **Microsoft Copilot experiences**; older `RetentionCompliance*` remains for supported older locations. See [cmdlet matrix](https://learn.microsoft.com/purview/retention-cmdlets) |
| A retention label cannot be assigned to prompt/response messages | Message retention and file/record labels are different mechanisms | Use Copilot retention policies for interaction messages and labels only for supported referenced files/exports; see [Copilot retention capabilities](https://learn.microsoft.com/purview/ai-m365-copilot) |
| Content retention is configured but older audit records are missing | Content policies do not extend UAL retention; Premium's one-year default is workload-specific | Review effective audit log retention and licensing separately; do not infer Copilot log retention from a mailbox/file policy or a seven-year scaffold schedule |
| Copilot messages remain visible after a deletion period | Backend retention processing is asynchronous or a hold retains content | Verify through eDiscovery, not UI visibility; processing typically runs over 1-7 days. Do not remove holds or purge data to test retention; see [retention processing](https://learn.microsoft.com/purview/retention-policies-copilot) |
| A named Graph workload scope does not return Copilot audit records | Service-specific `AuditLogsQuery-*` scopes are workload-restricted | Review `AuditLogsQuery.Read.All` and consent for the separately implemented Copilot query; see [API permissions](https://learn.microsoft.com/graph/api/security-auditcoreroot-post-auditlogqueries?view=graph-rest-1.0) |
| ExchangeOnlineManagement cannot load on PowerShell 7.0 | Local script minimum differs from module support | Match installed module, OS, and runtime to the [support matrix](https://learn.microsoft.com/powershell/exchange/exchange-online-powershell-v2); current 3.10.0+ requires PowerShell 7.6.0+ on supported Windows systems |
| Exported case counts or statuses look healthy without tenant checks | Counts and modes come from sample tier configuration | Keep the package marked sample; verify actual case access, data sources, and holds independently. `caseTemplate` is not a Microsoft template |
